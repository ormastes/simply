# Project Provenance Showcase — Local Research

<!-- codex-research -->

## Current state

- `data/registry.sdn` measures capability rows against one snapshot of
  `ormastes/simple` test output. The row links generated by
  `scripts/update_site.sh` always target the moving `main` branch.
- `data/tests.sdn` can name `repo:` paths as text but has no project identity,
  clone URL, branch, immutable commit, tag, release state, dirty-tree state, or
  per-project test receipt.
- `docs/index.html` is a generated single-page dashboard. It has no dedicated
  project/adoption page.
- The daily workflow only refreshes a local `simple` test snapshot when a
  binary happens to be installed; it has no checkout provenance or dirty-tree
  guard.
- The repository is intentionally an external showcase: it must reference
  sibling projects by URL, never vendor them.

## Gap

The site can say a capability has test evidence but cannot let a reader answer:
which project supplied it, at which immutable revision, which Simple version it
was checked against, whether the source tree was clean, or whether the proof is
current. The requested change needs a project-level proof receipt, a dedicated
advertising page, and runnable SSpec coverage over a deterministic simulator
before live cross-repository collection is trusted.
