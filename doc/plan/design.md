# simply — design

**simply** is the showcase + capability-registry repo for "whole-earth software in Simple".
It is Wave 0 of `doc/plan/implementation_map.md`: one truthful registry of every
capability row (I01–I38 infrastructure, A01–A31 application domains), a public
dashboard site generated from it, and the migrated Simple example corpus.

## Repo layout

```
doc/plan/            implementation map + this design
data/registry.sdn    capability registry — single source of truth
scripts/update_site.sh   regenerates docs/ from the registry (POSIX sh)
docs/                generated GitHub Pages site (glass theme)
examples/            migrated from ormastes/simple examples/
.github/workflows/daily-update.yml   daily cron: regenerate + commit
```

## Registry format (`data/registry.sdn`)

Pipe-separated rows, one capability each:

```
id|group|name|F|U|P|done|status|sspec
```

- `F/U/P` — feature / usability / performance scores (0–100, `-` = not measurable)
- `done` — `55%F + 25%U + 20%P` (renormalized when P is `-`)
- `status` — `declared | source_present | unit_verified | system_verified | usable`
- `sspec` — path or URL of the SSpec test (or `planned`) that proves the row.
  Future-implementation rows carry `planned` sspecs so the dashboard shows both
  what exists and what is promised. When rows get real sspec runs, the daily
  job will read test results and flip status automatically; until then status
  is hand-audited (see the map's ±10pt uncertainty note).

The dashboard groups rows, shows per-group and overall done %, and links each
row's sspec/test status.

## Dashboard generation

`scripts/update_site.sh` is plain POSIX sh + awk so it runs anywhere (CI has no
Simple toolchain yet). Upgrade path: replace with a Simple `.spl` generator run
by `bin/simple` once a released binary is consumable in CI, and drive `status`
from real SSpec results (`simple test --json`). The HTML is a single file with
the glass theme inlined — no JS frameworks, no build step.

## Theme

`docs/glass.css` mirrors the SimpleOS glass theme tokens
(`src/lib/common/ui/glass/` in ormastes/simple: blur surfaces, translucent
cards, accent gradients) reworked for a content site: higher contrast text,
light/dark via `prefers-color-scheme`. Intended to be the shared theme: changes
here should be folded back into the SimpleOS glass tokens and vice versa.

## Recursion prevention

simply showcases Simple, and Simple's example corpus now lives here. If
`simply` were ever vendored back into `ormastes/simple` as an example, and
simply vendored simple, checkouts would recurse. Prevention, three cheap layers:

1. **simply never vendors simple.** Sibling repos are referenced by URL only
   (see Related repos below). No submodule, no subtree.
2. `scripts/update_site.sh` fails hard if it finds a nested `simple/.git`,
   `simply/` directory, or any nested `.git` under `examples/` — so a vendored
   checkout can never pass CI.
3. `ormastes/simple` gitignores `examples/simply/` so an accidental clone
   inside its examples tree is invisible to git and cannot be committed.

## Examples migration

`examples/` (2,613 files) is copied from ormastes/simple at the migration
commit. Removal from ormastes/simple is deferred: deleting 2,613 files there
trips the tree-size push guards and needs a deliberate `--expect-files` landing;
until then ormastes/simple's copy is frozen (changes go here).

## Prior art consulted

- **CNCF landscape** (landscape.cncf.io) — data-file-driven capability catalog
  rendered to a static site; registry.sdn plays the role of its `landscape.yml`.
- **Kubernetes / LLVM** — monorepo core + satellite showcase repos, docs sites
  generated by CI cron, never hand-edited.
- **webkit.org / wpt.fyi** — public conformance dashboards where every claim
  links to a test run; the sspec column copies this.
- **NASA cFS, AUTOSAR, FHIR** — platform + domain-pack composition, already the
  backbone of the implementation map.

## Related repos (referenced, never vendored)

simple (core), simple-os, simple-erp, simple-ubs, simple-ide, simple-browser,
simple-riscv, simple-baremetal, simple-qemu, simple-restaurant, simple-payment,
simple-spostgre, svllm, simple_cuda_example, simple_deeplearning_study, Spipe.
Each should adopt the same `data/registry.sdn` row format + generator so every
project exposes a standardized dashboard the simply site can link or aggregate.

## New features this design needs from Simple (tracked as registry rows)

All three landed in ormastes/simple on 2026-08-26 (`db45479c256`):

1. Future-impl SSpec tests — `planned(name, reason)` marker reports as
   pending, never failed.
2. `simple test --json` status export: totals now include
   `total_skipped`/`total_pending`, per-file `skipped`/`pending`.
3. Runner-emitted grouping: a `groups` array (per-directory
   passed/failed/skipped/pending + `done_pct`) in the same JSON.

The dashboard consumes it via `data/test_results.json`: when present,
`update_site.sh` renders a "Test status" panel (totals + per-group done bars)
above the registry; when absent the panel is skipped. The daily workflow
refreshes the file automatically once a `simple` binary is installable in CI;
until then it can be produced locally and committed.
